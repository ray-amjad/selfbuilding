Your skills, as functions.
Running while you sleep.

Selfbuilding is an MIT, library-first TypeScript toolkit for building a software factory. Every SKILL.md folder becomes a typed Agent(). You compose agents in plain TypeScript, run them on any coding-agent harness, inside any sandbox provider, on a durable host you already use, and a human gets asked on Slack, Discord or a PR only when the agent needs one.

Typed agents

Results come back through an injected submit_result tool, so they're validated against a Zod schema. Text is never scraped.

Plain-TS composition

agent(), pipeline(), parallel(), step(), ask(), with no DSL and no graph builder.

One durability system

Resume from a journal on plain Node. On Trigger.dev, Inngest or Cloudflare Workflows, the host's own steps are the journal.

Bring your infra

7 harnesses × 7 providers × 3 chat channels. Every adapter passes a public conformance suite.

01 · ARCHITECTUREThe whole system on one page

Your factory code calls the core. The core holds no state in memory: it writes every completed step to a journal, and calls into four kinds of plug-in. The only part of Selfbuilding that runs inside a sandbox is a small runtime that drives the harness and talks to the host.

Journal replay

Each call is keyed by a callPath + stepKey hash. Unchanged calls replay from the journal, and only edited or new ones run live.

Budget & caps

One shared USD and wall-clock budget, a sandbox concurrency cap and a create-rate limiter per run.

Determinism

now(), random() and uuid() are journaled. An ESLint rule bans Date.now and Math.random in factories.

Events & errors

One event envelope for all sinks (stdout, OTel, Slack). Errors are named, typed and come with recovery fields.

The host reaches the sandbox by exec, never the other way

The sandbox needs no inbound port. The host polls the runtime with a long-poll wait; callbacks from the sandbox only wake the host sooner.

Only the supervisor writes the result

The agent calls submit_result, the supervisor checks it against the schema, and it either answers "accepted, stop now" or returns the errors so the agent can fix them and try again.

Secrets arrive as 0600 files

They're never env vars or baked into images. The agent's git token is read-only, and the host pushes the branch after the agent's processes have exited.

02 · RUN LIFECYCLEHow the pieces move

Four flows cover nearly everything: one agent call, a question to a human, a crash and resume, and passing work between sandboxes.

On every host, one agent() call becomes the same four parts: launch → wait → collect → accept. Launch and collect are host steps and safe to retry. The wait is one long durable wait, keyed on the launch id.
1
journalPlan. Compute callPath and stepKey. If the journal already holds a result for this key, return it right away (replay).
2
host · launchAcquire a sandbox. Record the intent before the remote call, then openOrCreate it with labels (selfbuilding.run, .step, .launch) and a finite lifetime. Upload the runtime if its SHA differs, stage the skill and input, and start the harness detached.
3
sandboxRun the turn. The supervisor boots, spawns the harness and streams normalised, redacted events to events.jsonl. The agent works, then calls submit_result. A bad shape is rejected with the errors and retried in the same run.
4
host · waitOne durable wait. The host sleeps cheaply. The runtime's callback (submitted, failed, ask…) wakes it early, and the reaper is the backstop if a callback never arrives.
5
host · collectRead the outcome. Read outcome.json + result.json, re-check the schema and size caps, upload artifacts (transcript, diff), and write the outcome record.
6
host · acceptFinal checks, then push. Run the Zod parse (refinements, transforms) and the done checks (tests, protected files untouched). The host pushes the branch with its own write token and opens or updates the PR as the GitHub App. Then the sandbox is disposed, or parked if it's shared.

Call states

planned→provisioning→booting→running⇄waiting (hot ask)⇄suspended (cold ask)→settling→succeededfailedcancelledtimed_out
unknown= contact lost, reconcile by label ·interrupted= dead turn found; default fail, opt-in resume-session

Fencing: every exec, callback and file the host reads carries (callId, attempt). An outcome from an older attempt is recorded as late_outcome and ignored. Once the journal marks a call terminal, nothing changes it.

One primitive, ask(). It's called from factory code, or by the agent through the ask_human tool. Selfbuilding decides whether to hold the sandbox open (hot) or park it (cold); the agent never chooses.

Hot wait: the answer comes quickly

1
sandboxAgent calls ask_human. The tool call blocks, and the call state becomes waiting, which pauses its time limits.
2
hostThe host creates the ask record and a durable waitpoint, then posts to every channel: Slack buttons, a Discord thread, a PR comment.
3
humanA human clicks or replies. The webhook handler (@selfbuilding/hooks) resolves the waitpoint.
4
sandboxThe answer goes into the inbox, the tool call returns, and the agent carries on in the same turn.

The default hot wait is 10 minutes, capped below each harness's own MCP tool timeout.

Cold wait: the answer is slow

1
sandboxThe tool returns suspended ("end your turn, you'll be resumed"). The runtime saves the harness session id and session file.
2
parkThe sandbox is parked in the strongest way the provider supports: memory pause(), otherwise a filesystem snapshot() then kill, otherwise a pushed work-in-progress branch then kill.
3
hostThe host's durable wait takes over, so no compute and no budget is spent while waiting.
4
resumeWhen the answer arrives, the host reopens or rebuilds the sandbox and resumes the session (--resume, exec resume, --session) with: "Answer to your question #2 from @alice via Slack: …"

AFK runs

With no human, every ask resolves by its declared policy: auto-answer, a default after a timeout, or fail. High-risk asks can only fall back to a safe choice. Asks from a shared sandbox are hot-only, so fork() first if you need a long question.

Crash, edit your factory, re-run with the same runId. Calls whose identity is unchanged return their recorded result instantly, and only the first edited call onwards runs live. A turn that was interrupted mid-flight is never silently re-run.
1
Run 1. implement ✓, review-0 ✓, then fix-0 starts… and the process crashes.
2
You edit the fix prompt and run npx selfbuilding resume <runId>.
3
replayimplement, review-0 and the exec and push before them are served from the journal.
4
sandboxThe shared box is reused only if it passes every safety check. Otherwise it is rebuilt from the implement checkpoint (git by default).
5
livefix-0 (the edited prompt) and everything after it run live.

What a call's identity includes

stepKey = sha256({ callPath, skill/prompt, input, options, history }), encoded as 26 characters. callPath is readable (pipeline#0/[issue-412]/stage#1/ImplementSpec#0). Counters are kept per name, so adding a CodeReview doesn't shift ImplementSpec's path.

Epochs

Resuming after a terminal failure starts a new epoch, which never serves a cached failure. refresh: ["list-issues"] re-runs a named step() on purpose.

One durability system

Plain Node uses fileJournal() or sqliteJournal(), with a lease so two processes can't drive one run. On Trigger.dev, Inngest or CF Workflows the host's step memo plus the result store is the journal; it's never both.

pipeline() has no barrier: each item moves to its next stage as soon as it's ready. parallel() is the explicit barrier. In both, a failed child becomes null and the error goes on the event stream. A direct agent call throws.
1
stepstep("list-issues") fetches 20 issues once, and replay sees the same list.
2
stage 1PlanIssue on a cheaper model, in a fresh read-only sandbox. Returning null drops that item.
3
stage 2ImplementSpec in its own fresh sandbox, then the host pushes selfbuilding/<runId>/….
4
stage 3CodeReview of the branch. If it approves, a step("open-pr-412") opens the PR.

Scheduling

Up to concurrency.sandboxes agents at once, with later stages scheduled first so finished work drains. One stage throwing drops only its own item.

Incremental re-runs

Items are keyed (key: i => `issue-${i.number}`). A 21st issue appearing replays the existing 20 and runs only the new one.

Budget

Each agent gets a slice: min(remaining, perAgent.usd ?? usd / sandboxes), and the unused part goes back when it ends. When the budget runs out, the call throws BudgetExceededError.

03 · SANDBOX PLACEMENTSame sandbox, or different, with information passed between

You choose where each agent runs. The default is a fresh sandbox per call: isolated and safe to replay. Sharing a working tree is opt-in, through an explicit handle.

Fresh (default)
sandbox: "fresh"
ImplementSpecbox A
CodeReviewbox B

Each call gets its own sandbox, closed when the call ends. Information passes as typed results.

Shared handle
await using box = sandbox({…})
Implement → Fix → Fixbox W

Consecutive agents share one working tree. Fast, nothing to copy. One agent runs at a time per handle, and asks are hot-only.

Fork
box.fork(3) · box.snapshot()
judge-0fork 0
judge-1fork 1
judge-2fork 2

Copies of one sandbox's state, so parallel judges can edit and run tests without touching each other.

Branch handoff

ImplementImpello
ReviewDocker · Codex

The lasting way to hand work across providers, harnesses or days. The reviewer sees only the pushed branch.

04 · API BY EXAMPLEWhat it feels like to use

All primitives are imported from @selfbuilding/core and find the current run implicitly (there's no ctx). Harness, sandbox and journal are values, never strings, and the model is set on the harness value.

# Node 22.12+, Docker, an Anthropic API key or a Claude subscription token
npm i @selfbuilding/core @selfbuilding/agents @selfbuilding/harnesses @selfbuilding/sandbox-docker zod
npm i -D selfbuilding
npx selfbuilding init --harness claude-code --provider docker --host node
npx selfbuilding doctor            # lists every missing credential or setting at once
npx selfbuilding run factories/review-pr.ts --input '{"url":"https://github.com/acme/api/pull/412"}'
npx selfbuilding watch <runId>    # live transcript
npx selfbuilding resume <runId>   # after a crash or an edit

factories/review-pr.ts

import { factory } from "@selfbuilding/core";
import { CodeReview } from "@selfbuilding/agents";
import { z } from "zod";

export default factory(
  { name: "review-pr", input: z.object({ url: z.url() }) },
  async ({ url }) => {
    const review = await CodeReview({ target: { kind: "pr", url } });
    return review.result;  // { verdict: "approve" | "request_changes" | "comment", summary, findings[] }
  },
);
export const ImplementReviewFix = factory(
  { name: "implement-review-fix", input: z.object({ repo: z.string(), spec: z.string() }) },
  async ({ repo, spec }) => {
    await using box = sandbox({ provider: impello({ template: "selfbuilding-claude-code" }), repo, label: "work" });

    phase("implement");
    await ImplementSpec({ spec }, { sandbox: box, label: "implement" });   // throws on failure

    for (let round = 0; round < 3; round++) {
      const tests  = await box.exec("pnpm test", { timeout: "15m" });
      const branch = await box.push();                              // selfbuilding/<runId>/work

      // independent reviewer: fresh sandbox, different harness, sees only the branch
      const review = await CodeReview.settled(
        { target: { kind: "diff", base: "main", head: branch.name } },
        { repo, harness: codex({ model: "<codex-model-id>" }), label: `review-${round}` },
      );
      if (!review.ok) break;
      if (review.value.result.verdict === "approve" && tests.exitCode === 0) break;

      await agent({                                                  // inline agent, same shared tree
        name: "fix", prompt: "Address every finding. Keep the diff minimal. Run the tests.",
        input: { findings: review.value.result.findings },
        output: z.object({ summary: z.string() }),
        sandbox: box, label: `fix-${round}`,
      });
    }
    return { branch: (await box.push()).name };
  },
);
export const Triage20 = factory({ name: "triage-20", input: z.object({ repo: z.string() }) }, async ({ repo }) => {
  const issues = await step("list-issues", () => github.listIssues(repo, { label: "agent-ok", limit: 20 }));

  const prs = await pipeline(
    { key: (i) => `issue-${i.number}` },
    issues,
    async (issue) => {                                                  // stage 1: plan (cheap model)
      const p = await PlanIssue({ issue: issue.number }, { repo, harness: claudeCode({ model: CHEAP }) });
      return p.result.feasible ? p : null;                            // null drops the item
    },
    (plan) => ImplementSpec({ spec: plan.result.spec }, { repo }),       // stage 2: own fresh sandbox
    async (impl, { item }) => {                                         // stage 3: review, then PR
      const r = await CodeReview({ target: { kind: "diff", base: "main", head: impl.artifacts.branch!.name } }, { repo });
      if (r.result.verdict !== "approve") return null;
      return step(`open-pr-${item.number}`, () => github.openPr({ repo, head: impl.artifacts.branch!.name }));
    },
  );
  return { prs: prs.filter(isPresent) };
});
export const JudgePanel = factory({ name: "judge-panel", input: Z }, async ({ repo, branch }) => {
  await using box = sandbox({ provider: impello({ template: "selfbuilding-claude-code" }), repo, branch });
  await box.exec("pnpm install --frozen-lockfile && pnpm build", { checkpoint: true });

  const forks = await box.fork(3, { mode: "best" });             // 3 slots taken atomically
  const harnesses = [claudeCode({ model: A }), codex({ model: B }), opencode({ model: C })];
  const verdicts = await parallel(forks.map((f, i) => () =>
    f ? Judge({ rubric: RUBRICS[i] }, { sandbox: f, harness: harnesses[i], label: `judge-${i}` })
      : Promise.resolve(null)));                                       // failures → null
  const votes = verdicts.filter(isPresent);
  return { pass: votes.length >= 2 && votes.filter(v => v.result.pass).length * 2 > votes.length };
});

Testing strategy

Scripted harness

A fake harness that replays a script, for deterministic end-to-end runs with no model at all.

Conformance

Every provider runs the same suite, which includes injected 503s and timeouts. It runs on Docker locally and on real providers in CI.

emulate.dev

Local GitHub and Slack emulators for PR, check-run and button flows. Discord gets its own fake.

Live smoke

Nightly real-model runs on your subscriptions, capped, plus the factory reviewing its own PRs.

06 · FAILURE MODESWhat breaks in production, and the mechanism that stops it

Each of these is enforced in code and tested. None of them relies on a convention.

FailureWhat goes wrongMechanism
Leaked sandboxesA sandbox keeps running and billing after its agent is gone, fills the concurrency cap, and then nothing new can start.Intent is journaled before create(). Every sandbox has a finite lifetime and labels. reap() sweeps the provider's actual list on a cron. A refused pause is a typed outcome, never a throw.
An outage read as "not found"A 5xx during lookup is treated as "no sandbox", so live work is rebuilt over or a message is dropped.find() returns null only for a genuine miss, and everything else throws SandboxUnavailableError. Only explicit kills and positive 404s destroy anything.
A lookup that wakes thingsChecking a paused sandbox resumes it, which undoes every park.find() never wakes. Pause is done by id, never through a connected handle.
Ghost refsA record says "paused" but the sandbox is gone, so every retry fails the same way forever.openOrCreate rebuilds from a checkpoint and converges on the new sandbox.
Double-run on retryA host retry starts a second agent turn.Launch is idempotent (it checks outcome records and markers) and fenced by (callId, attempt). A late outcome is ignored.
Harness CLI driftA new CLI version changes its stream format and parsing breaks silently.The default version is 'tested', with pinned versions plus parser fixtures and a nightly probe per harness.
Secrets in snapshotsA key is baked into an image, snapshot or pushed branch.Secrets arrive as 0600 files only. Snapshots and pushes are checked by an exact-value scan. The agent token is read-only.
Silent skipsOne missing token quietly disables everything.Errors are loud and named. selfbuilding doctor lists every missing setting at once.
